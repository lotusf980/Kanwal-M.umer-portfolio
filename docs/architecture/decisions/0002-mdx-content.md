# 2. Author content in MDX with custom components

- Status: accepted
- Date: 2026-08-02

## Context

Case studies and blog posts need richer than plain Markdown: callouts, metric callouts, and syntax-highlighted code. We also want prose typography that matches the design system.

## Decision

Author content as **MDX** compiled at build time by `@content-collections/mdx`. The compiler runs:

- `rehype-slug` for heading IDs.
- `rehype-pretty-code` (shiki) with a light/dark theme map for code blocks.
- Heading extraction (h2/h3) into a `headings` field powering the table of contents.

Custom MDX components (`Callout`, `Metric`) live in `src/components/mdx/` and are registered via a shared `mdxComponents` map consumed by `MdxContent`. Pages can extend them per route.

## Consequences

- Prose renders with design-system typography (the `.prose` utility) and theme-aware code highlighting.
- Headings and TOC stay in sync because IDs are generated by the same slugger.
- Authors must use the supported component set; unknown components fall through to raw HTML only if marked allowed.
- Adds `rehype-pretty-code`, `rehype-slug`, `shiki`, and `github-slugger` as dependencies.
